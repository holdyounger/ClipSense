# Clipboard Spike — 剪贴板历史 Demo

> **目的（spike）**：验证基于 Electron 实现剪贴板历史、内容恢复、窗口贴边交互和选中项粘贴的核心技术链路，不等同于完整产品。

## 一、当前能力

- 轮询监听系统剪贴板，默认间隔 `600ms`
- 持久化剪贴板历史，支持文本、富文本、图片和文件条目
- 使用 Electron `safeStorage` 加密历史元数据和图片；不可用时降级为明文并输出告警
- 支持内容去重和可配置历史上限（100 / 200 / 500 / 1000 / 5000）
- 点击「复制」按钮，将指定条目写回系统剪贴板
- 双击指定条目：
  1. 将该条目写入系统剪贴板
  2. 向原目标窗口发送一次 `Ctrl+V`
  3. 粘贴指定历史条目，而不是当前原有剪贴板内容
- 文件条目单击预览，可在 Windows Explorer 中打开并定位对应文件
- 空格、Tab、换行等纯空白内容使用可见符号预览：
  - 空格：`␠`
  - Tab：`⇥`
  - 换行：`↵`
- 窗口支持贴边、拖拽、定时推出隐藏和鼠标触碰边缘唤出
- 隐藏后保留独立的边缘触发条，主面板和触摸条使用不同窗口
- 搜索框支持按需获取焦点，不影响双击条目时向原目标窗口粘贴

## 三、手动验证清单

### 剪贴板历史

1. 启动应用，确认剪贴板历史面板显示。
2. 在任意编辑器或浏览器中按 `Ctrl+C`。
3. 等待不超过约 `0.6 秒`，复制内容应出现在列表顶部。
4. 再复制其他内容，确认历史继续新增。
5. 点击条目的「复制」按钮，在其他窗口按 `Ctrl+V`，确认内容正确。
6. 点击「✕」删除条目，或使用菜单清空全部历史。

### 指定条目粘贴

1. 先在目标编辑器中放置输入光标。
2. 唤出 Clipboard Spike 面板。
3. 双击某个历史条目。
4. 确认目标编辑器只收到一次 `Ctrl+V`，且粘贴的是被双击的条目。
5. 验证文本、富文本、图片、普通文件和 `.exe` 文件等类型。

> 双击流程会临时覆盖系统剪贴板，因为 Windows 没有通用接口可以在不修改系统剪贴板的情况下，让任意目标应用执行“粘贴指定历史条目”。当前实现尚未自动恢复原剪贴板。

### 文件条目

- 单击文件预览：在 Explorer 中打开文件所在目录并选中对应文件。
- 多文件条目：默认定位到第一个文件。
- 双击文件条目：按文件剪贴板格式回写后执行 `Ctrl+V`，用于在 Explorer 等目标窗口中粘贴文件。

### 窗口交互

1. 按全局快捷键 `Ctrl+Shift+V` 唤出或隐藏窗口。
2. 窗口显示时，鼠标移出面板后等待约 3 秒。
3. 面板会向最近的屏幕边缘滑出并渐隐。
4. 隐藏后，屏幕对应边缘保留触发条。
5. 鼠标触碰该侧触发条后，面板重新显示。
6. 拖拽 header 后再次隐藏/唤出，确认位置可以恢复。
7. 点击搜索框，确认可以正常输入和过滤历史。

## 四、核心实现

### 剪贴板监听与历史

```text
tick()
  → 读取系统剪贴板
  → 根据类型生成 hash
  → 与最近 hash 和会话去重集合比较
  → 构造历史条目
  → 持久化并通知渲染层
```

主要文件：

- `src/main/clipboard-monitor.js`：读取、分类、去重、历史管理和剪贴板回写
- `src/main/storage.js`：历史元数据与图片持久化、加密和恢复
- `src/main/index.js`：Electron 主进程、IPC、窗口和托盘
- `src/main/input-simulator.js`：通过 Windows `keybd_event` 发送一次 `Ctrl+V`
- `src/main/edge-detector.js`：贴边、倒计时、推出动画和边缘唤出
- `src/renderer/main.js`：搜索、固定、倒计时和 UI 状态
- `src/renderer/renderer.js`：文本、图片、富文本、文件条目渲染与交互
- `src/renderer/preload.js`：安全暴露 IPC API

### 持久化位置

由 `app.getPath('userData')` 决定：

- `clipboard-history.json`：历史元数据
- `clip-images/<id>.bin`：独立保存的图片数据
- `clip-history-config.json`：历史上限等配置

在 Windows 上通常位于 Electron 应用的用户数据目录；具体路径以运行时 `app.getPath('userData')` 返回值为准。

### 文件粘贴格式

Explorer 文件粘贴使用 Windows `FileNameW` / `CF_HDROP` 兼容路径数据，不使用普通 URI 文本代替文件剪贴板。

## 五、已知限制与待验证项

- 尚未完成真实 Windows 实机验证，尤其是：
  - `focusable: false` / `showInactive()` 与搜索框按需获取焦点的交互
  - `keybd_event` 是否始终只触发一次 `Ctrl+V`
  - 文本、HTML/RTF、图片和 Explorer 文件粘贴兼容性
  - 左右屏幕边缘触发条的显示宽度、圆角和鼠标命中范围
- 当前双击指定项会覆盖系统剪贴板，尚未实现 Ditto 式“粘贴后延迟恢复原剪贴板”。
- `safeStorage` 在 WSL 或无系统钥匙串环境可能不可用，会降级为明文存储并告警。
- 图片已具备持久化链路，但完整的跨应用图片粘贴仍需在 Windows 上验证。
- 文件不存在或已移动时，Explorer 定位操作会返回错误。
