# 自动打标签

| 版本 | 日期 | 变更内容 | 影响范围 |
|------|------|----------|----------|
| V0.1 | 2026-09-09 | 初稿：竞品核实、MVP 标签集定义、关键产品决策、验收标准 | 全新功能，涉及主进程采集链路、渲染列表、托盘菜单 |

## 一句话描述

在剪贴板文本条目入库时用**纯本地规则**自动打上类型标签（URL / 邮箱 / 验证码 / 代码片段 / 敏感信息），条目上以 chip 展示、支持按标签筛选，为后续语义搜索（方向 B）与敏感防护（方向 C）打好结构化地基。

## 背景与调研依据

### 需求源头

- 《AI拓展方向调研-2026-09-08》方向 B 提出「后台自动打标签：代码片段/URL/邮箱/地址/验证码/敏感信息」，原排期在 P2、依赖方向 A 的 AI provider 层。本 PRD 论证并采用「规则层先行」方案提前落地（论证见决策 D1）。
- 隐私红线（调研报告 §三）：默认本地、敏感条目不进 AI、出网可解释。纯本地规则打标天然满足全部三条。

### 自身能力现状（✅ 已核实，代码级）

- `src/common/link-utils.js` 已有链接识别（入库时算 `item.links`），是规则打标的现成雏形。
- `src/main/clipboard-monitor.js` 的 `_migrateLinks()` 已建立「旧数据补算字段 + 回写存储」的幂等迁移先例，标签可复用同一模式。
- `src/main/storage.js` JSON + safeStorage 加密、历史上限默认 500；标签作为 item 普通字段随现有链路持久化，无需新存储设施。
- 渲染层为 innerHTML 全量重建 + 事件委托（`.ctx-lockstep/PROJECT.md` 硬性结论），chip 与筛选交互必须遵守。
- 现有搜索为子串匹配 + `date:` 前缀语法（`renderer/main.js`，语义已被 PROJECT.md 固化），标签筛选需与之自然融入、不改动既有语义。
- 设置无独立页面，全部走托盘右键菜单（「历史上限」「自动隐藏倒计时」均为 radio 子菜单）——标签设置应跟随此模式。

### 空位结论

✅ 已核实的主流竞品中，**没有一家把「内容自动打标签」做成内置、开箱即用的能力**：CopyQ 能力最强但要求用户自己写脚本/规则；EcoPaste/PasteBar 有识别无标签化。ClipSense 以「内置标签集 + 零配置」切入，成本低于任何 AI 方案，且与「不夺焦」同属克制哲学叙事。

## 关键产品决策

### D1：MVP 走纯本地规则打标，不等 AI provider 层 —— 推荐

- **理由**：
  1. 依赖解耦：路线图 P2 的前提是「标签需要 AI 语义理解」，但 MVP 标签集（URL/邮箱/验证码/代码/敏感）全部可用确定性规则高置信识别——调研报告方向 C 自己写明「规则层（正则熵检）就能覆盖 80%，AI 只兜底」。
  2. 隐私红线天然满足：零网络、零 AI，规避「用户密码被送去分析」类事故，也无出网解释负担；对齐 PowerToys「非 AI 动作全本地」的事实标准。
  3. 竞品空位：已核实竞品无一内置开箱即用自动标签（CopyQ 需用户写脚本），零配置即差异化。
  4. 工程连续性：link-utils + _migrateLinks 已验证同款模式，成本最低；并为方向 B 预留「规则打标打底 → AI 兜底增强」的演进路径，而非推翻重来。
- **备选（被否）**：等 AI provider 层完成后用 LLM 批量打标——引入 BYOK/出网隐私负担；无 key 用户不可用；排期后置数周；而它能带来的语义级标签（如「地址」）不在 MVP 标签集内。

### D2：标签呈现 = 条目 chip + 按标签筛选，与现有搜索交集组合 —— 推荐

- **理由**：EcoPaste 的内容类型过滤（✅ 已核实）验证了筛选价值；chip 轻量不占空间（窗口 560px 高度约束）；与搜索交集组合可复用现有过滤管线，交互心智一致（都是「缩小范围」）。
- **备选（被否）**：① 仅打标不筛选——用户看不见的价值等于没做；② 标签作为独立侧栏——窗口宽度与「边缘唤出」窄窗形态冲突。

### D3：「敏感信息」只打标不拦截，与方向 C 的边界 = 打标是 C 的检测地基 —— 推荐

- **理由**：方向 C 的核心动作（跳过采集/打码/PIN/过期）每项都改变数据流向，是独立的安全决策，应单独立项评审；「识别出这是敏感信息」这层检测能力是 C 与 B 共用的地基，先行落地可复用。本期敏感条目照常入库、照常展示，仅 chip 中性提示——用户知情权先行，处置能力后行。
- **风险提示**：chip 提示对部分用户可能造成轻微焦虑，文案需中性（「敏感」而非「危险」）。
- **备选（被否）**：本期顺带「敏感条目跳过采集」（EcoPaste 模式）——用户会误以为「复制失败」，属行为突变，需独立引导与开关，塞进打标版本会稀释焦点。

### D4：设置粒度 = 总开关 + 逐标签开关；自定义规则放二期 —— 推荐

- **理由**：总开关满足「不想被打标」的用户；逐标签开关成本几乎为零（同一识别管线），且「验证码」「敏感」两类有误报打扰风险，应可单独关闭。自定义规则需要规则冲突处理、安全审查（恶意正则风险）、规则管理 UI 三件套，超出 MVP 收益；CopyQ 的 tags 配置表模式（✅ 已核实）可作二期形态参考。
- **备选（被否）**：① 无开关强制开启——违背「可解释、可关闭」的克制哲学；② MVP 就做自定义规则——收益/成本比不成立。

## MVP 标签集定义

> 只定义判定意图与典型例子；具体识别实现（正则/启发式/阈值）由架构师设计。优先级用于多标签共存时的排序展示。

| 优先级 | 标签 | 判定意图（识别什么） | 典型例子 | 备注 |
|--------|------|----------------------|----------|------|
| 1 | 链接 | 内容整体是 URL，或长文本内含 URL | `https://github.com/holdyounger/ClipSense`、`www.example.com/a?b=1` | 直接复用现有 extractLinks 识别结果，无新增识别成本 |
| 2 | 邮箱 | 内容整体是邮箱地址，或长文本内含邮箱 | `dev@example.com` | 与链接可共存（文本同时含 URL 和邮箱） |
| 3 | 验证码 | 短数字/字母数字组合 + 上下文像一次性口令（短信/邮件验证码场景） | 「验证码 582914，5 分钟内有效」「Your code is 492031」 | 误报主源是普通短数字（订单号/纯数字），需上下文线索；宁缺勿滥 |
| 4 | 代码片段 | 多行结构化内容、常见代码/命令行特征（缩进/括号/关键字） | SQL 语句、JS 函数、`git push -f origin main`、JSON 对象 | 对齐 PasteBar「代码语言检测」先例；窄判定，不追求覆盖广 |
| 5 | 敏感信息 | 疑似密码、密钥、token、银行卡/信用卡号等凭据或强隐私内容 | `-----BEGIN ... PRIVATE KEY-----`、`AKIA...` 密钥、16 位卡号 | 只打标不拦截（D3）；高置信才打，拿不准不打 |
| — | 普通文本 | 以上全部未命中 | 随手复制的句子、段落 | 不展示 chip；筛选条中对应「全部」的自然结果 |

- 多标签：一条内容可同时命中多个标签（如内嵌 token 的 URL = 链接 + 敏感），按优先级排序，最多展示 2 个 + 溢出计数。
- 空白/极短条目（如纯空格换行）不打标。
- 「地址」（调研报告方向 B 原提及）因中文地址规则误报率高、MVP 内价值最低，裁剪出本期，二期随 AI 标签一并评估。

## 交互 & UI

### 条目 chip 展示

- 位置：条目 meta 行（时间 · 字数之后）追加标签 chip；链接条目的 🌐 按钮、Ctrl+单击既有交互不变。
- 形态：小号圆角 chip，仅文字（如「链接」「验证码」）；图片/文件等非文本类型不参与打标、不显示 chip。
- 「敏感信息」chip 用区别色（如琥珀色），不做遮罩/模糊（见 D3）。
- 多标签按优先级最多展示 2 个，超出以「+N」表示。

### 按标签筛选

- 搜索框下方增加一排标签筛选条：「全部 ｜ 链接 ｜ 邮箱 ｜ 验证码 ｜ 代码 ｜ 敏感」，点击筛选，再点取消回全部。
- 筛选条只显示当前历史中存在该标签的项，避免空标签占位。
- 筛选与搜索框组合生效：先按标签过滤集合，再在集合内做子串 / `date:` 匹配（交集）。
- 窗口关闭/重开不保留筛选状态（边缘唤出的短交互场景）。
- 本期不扩展搜索语法（`tag:` 前缀不做），避免与已固化的 `date:` 前缀解析逻辑耦合；二期再评估。

### 设置入口

- 沿用托盘右键菜单：新增「自动打标签」子菜单 = 总开关（checkbox，默认开）+ 各标签独立开关（checkbox，默认开）。
- 关闭语义：仅影响「展示与继续打标」，不删除已打的标签数据（重开开关即恢复；数据清除交给用户主动删条目/清空）。

### 升级兼容

- 老用户升级后首次启动对存量 text 条目补算标签（幂等迁移），无感知、无弹窗、无引导教程。

## 技术约束（要点级，实现细节归架构师）

- 打标只发生在主进程入库时（type=text），结果作为 item 字段持久化；渲染层只消费字段做 i18n/样式映射，不重复计算。
- 识别器放 `src/common/`（无 DOM、双端可 require/window 挂载），沿 link-utils 惯例；URL 识别必须复用 `extractLinks`，不另起判定（避免「链接条目无链接标签」的不一致）。
- 存量数据迁移必须幂等（显式标记「已识别、无标签」，仿照 links 的显式 null 先例），迁移失败静默降级、不影响入库。
- 渲染层 innerHTML 全量重建：chip 与筛选条的交互一律容器委托，不得逐元素挂监听；交付前过 DOM 桩 harness（PROJECT.md 硬性结论）。
- 性能：打标位于 600ms 轮询链路内，必须是同步轻量纯计算（禁止网络请求/异步模型调用）；500 条存量迁移应在启动时一次性完成且不卡 UI。
- 隐私红线：打标 100% 本地、零网络；标签字段随现有 safeStorage 加密链路落盘，不新增明文存储；safeStorage 不可用降级路径下行为与现有条目一致。

## 约束 & 不做范围

- 不做 AI/LLM/embedding 参与（属方向 B 后续，等 AI provider 层；演进路径见 D1）。
- 不做「地址」标签（中文地址误报率高，二期评估）。
- 不做拦截/隐藏/打码/PIN/自动过期——全部属方向 C（敏感防护），本期只打标（见 D3）。
- 不做用户自定义规则/正则编辑器（二期候选，见 D4）。
- 不做手动编辑标签（增/删/改单条目的标签）；用户反馈强烈时二期评估手动+自动标签合并策略。
- 不做图片/文件/富文本条目打标（file 已有类型化展示，image 无文本可判；富文本 plainText 打标列二期增强）。
- 不做搜索语法扩展（`tag:` 前缀）、按标签聚合视图/统计页。

## 验收标准

### 功能

1. 复制典型样本（链接/邮箱/验证码/代码/敏感 各至少 2 例）后，对应条目出现正确 chip；普通文本无 chip。
2. 多标签条目（含 URL 且含 token 的文本）按优先级展示 ≤2 个 chip + 溢出计数。
3. 点击筛选条标签只显示含该标签的条目；与搜索词、`date:` 语法组合时为交集结果；再点取消恢复全列表。
4. 托盘菜单可关总开关或单标签；关闭后新条目不再打该标签、列表不再显示该类 chip，已打数据保留，重开即恢复。
5. 升级场景：v1.0.2 存量历史（含 text 条目）升级后首次启动自动补打标签，第二次启动不重复计算（幂等）。

### 边界与质量

6. 打标过程零网络请求（设计评审 + 代码审查确认）。
7. 单条打标同步轻量，不阻塞轮询归档；500 条存量迁移不卡 UI（量化指标由架构师定，建议 < 1s）。
8. innerHTML 全量重建后 chip 与筛选条交互正常（事件委托验证，过 DOM 桩 harness）。
9. 异常输入（空串、超长文本、纯空白、emoji 混排）不抛错、不影响入库。
10. 加密不可用降级环境下标签随条目正常持久化与恢复。
11. i18n：中英文标签名与筛选条文案完整。
