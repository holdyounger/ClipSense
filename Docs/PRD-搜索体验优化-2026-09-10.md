## 一句话描述

搜索入口从 footer 上移到 header（放大镜图标点击展开），Esc 退出搜索并清空，Ctrl+F 在面板持键盘焦点期间直达搜索输入；搜索语义（子串 + `date:` 前缀）与标签筛选交互完全不变。

## 背景与现状（代码事实，✅ 已核实 2026-09-10）

- 搜索框常驻 footer：`index.html` footer 内 `.footer-main` = `.search-box`（🔍 + `#searchInput`）+ `.stats`；其下为标签筛选条 `#tagFilter`（v2，无标签时 hidden）
- header 现有结构：`h1#title`（左）+ `.header-actions`（右：倒计时徽标 `#countdownBadge`、固定按钮 `#pinBtn`、菜单 `#menuBtn` + dropdown）——360px 宽度下已较满
- **不夺焦架构（本 PRD 的核心约束）**：主窗口 `focusable: false`（`index.js:60`；`index.js:651`「默认不抢目标窗口焦点；搜索框点击时由 focus-search IPC 按需开启」）。键盘输入只在 `focus-search` IPC（`index.js:463-471`：`setFocusable(true)` + `focus()` + 兜底 `setSearchActive(true)`）之后到达渲染层；`blur-search`（:474-480）反向恢复并挂起解除
- 现有联动链：`searchInput` pointerdown → `focusSearch()`；blur → `blurSearch()` + `setSearchActive(false)`（自动隐藏恢复）；主进程与渲染层 blur 双保险
- 搜索语义已固化：`searchQuery` 子串 + `date:` 前缀（PROJECT.md），`filterHistory` 顶部叠加标签筛选交集（v2）
- Esc 现状：全代码库零注册（空白域，已核实）——本需求是首次定义

## 交互与 UI（三点逐一）

### 1. 搜索栏上移 header（图标点击展开，非常驻）

- `.header-actions` 内新增放大镜图标按钮（SVG，与 pin/menu 同风格；位置拍板 #3，推荐最左）
- 点击图标 → 搜索展开态：`h1#title` 与倒计时徽标隐藏（360px 空间让渡），输入框展开占满 header 中部（flex），调用既有 `focusSearch()` 后自动聚焦；pin/menu 保持可见可点
- **收起即清词（统一规则，拍板 #2）**：任何收起路径（输入框 blur / 点击 header 外区域 / Esc）一律清空搜索词并退出展开态——列表回到未过滤态，杜绝「列表被过滤但看不到搜索框」的隐形过滤不一致
- **重显自洽规则**：窗口自动隐藏时若处于搜索态（词非空），重新唤出后搜索框**自动视觉展开但不抢焦点**（列表过滤态与搜索框可见性强一致）
- 动画：CSS width/opacity 过渡约 150ms，零新依赖
- footer：移除 search-box 后 `.footer-main` 仅剩 stats，`#tagFilter` 紧随其下不变

### 2. Esc 退出搜索 + 清空（单段化）

- Esc 语义 = **清词 + 收起 + 恢复自动隐藏倒计时**，一次完成；**不隐藏窗口**（差异说明：PowerToys/Ditto/CopyQ 的 Esc 会关面板/两段式，但 ClipSense 面板存在非搜索浏览态，误按 Esc 付出「面板消失」代价过重——价值不符）
- 展开态 + 有词 → 清空 `searchQuery`（含 `input.value`）+ 刷新列表 + 收起 + `blurSearch()` + `preventDefault()`
- 展开态 + 无词 → 收起 + `blurSearch()`（同样清词规则，无词则等效收起）
- 未展开 → Esc 无动作（不注册窗口级行为）
- **标签筛选态不被 Esc 清除**（独立维度，拍板 #1 确认推荐：不清）
- IME 安全：`e.isComposing === true` 时忽略
- 实现位置：`searchInput` keydown + document keydown 兜底；header 为静态 DOM 可直接挂监听（委托纪律仅约束列表区）

### 3. Ctrl+F 直达搜索（诚实边界）

- 实现：renderer `document` 级 keydown——`e.ctrlKey && !e.altKey && !e.shiftKey && e.code === 'KeyF' && !e.isComposing` → `preventDefault()` + 进入展开态 + `focusSearch()` + 输入框聚焦
- **明确不做 `globalShortcut`**（绝不劫持系统级 Ctrl+F）
- **生效域 = 面板持有键盘焦点期间**（架构属性，非缺陷）：Alt+V 刚唤出、未点击搜索框时，面板无键盘焦点，Ctrl+F 物理不可达——此时按键属于前台应用。**「唤出时自动聚焦」明确禁止**：会破坏双击粘贴的焦点模型（paste-bridge 依赖面板不夺焦），不符合产品核心卖点
- **v0.3 修订（2026-09-10 实机反馈）**：生效域扩展为「面板任意点击后即生效」——document 级 pointerdown 统一走 focusSearch（幂等），用户点击面板任意处后 Ctrl+F/打字即可用；Alt+V 唤出仍不自动聚焦（不夺焦承诺不变，双击粘贴实机回归项保留）
- **v0.3 机制修正（实机二轮反馈后定位）**：焦点链失效真因 = NOACTIVATE 样式移除后未重新 show()——`SetWindowLong` 样式变更对已可见窗口不触发重新激活，moveTop/focus/webContents.focus 全部只是置顶+进程内设焦，键盘输入仍走前台应用。修复 = focus-search 链路在 setFocusable(true) 后追加 show()（重新激活）；⚠️ 点击 header 空白区（drag 区）事件不进渲染层，需点搜索图标/按钮/列表等非 drag 区
- **v0.4 焦点模型回切（实机三轮反馈终局）**：show() 修复后面板已能拿到 OS 键盘焦点（IME 随焦点切换可证），但 NOACTIVATE 模型下键盘交互仍不可靠——回切为标准可聚焦窗口（移除 focusable:false 与 _applyNoActivate 调用），焦点类问题整类消除；Alt+V 唤出/点击面板即持焦点，边缘被动显示（showInactive）仍不夺焦；双击粘贴回归为最高优先验证项
- 实际使用路径：点击搜索图标（或搜索框）→ 键盘启用 → 此期间 Ctrl+F 随时直达搜索；blurSearch 后失效
- 已有搜索词时按 Ctrl+F → 仅重新聚焦（光标到末尾），不清词

## 技术约束（要点级）

- 搜索语义（子串 + `date:`）与 `filterHistory` 标签交集零改动——验收含「同词对比回归」（迁移前后同词结果一致）
- 自动隐藏联动复用 focusSearch / blurSearch / setSearchActive 既有链路，零新增 IPC
- **零改动区**：`date:` 语义、标签筛选条交互、edge-detector 挂起机制、paste-bridge 全部不动
- header 静态 DOM 直接挂监听；列表区守容器委托纪律
- 零新增运行时依赖；动画纯 CSS

## 约束与不做范围

- 不做全局快捷键（Ctrl+F 不抢系统级）
- 不做唤出时自动聚焦（拍板明确禁止，保护粘贴焦点模型）
- 不改 `date:` 语义、标签筛选逻辑；不做搜索历史/联想
- Esc 不注册窗口隐藏/关闭语义

## 验收标准

1. 点击 header 搜索图标 → 输入框展开、自动聚焦、可直接打字（focusSearch 生效）
2. **收起即清词**：blur / 点外 / Esc 任一路径收起后列表回到未过滤态，无隐形过滤
3. Esc 三态正确：有词清空收起、无词仅收起、未展开无动作；IME 组合中不触发；**窗口不隐藏**
4. Ctrl+F：面板持键盘焦点期间展开+聚焦；未持焦点时按键不产生本应用行为（落到前台应用，属预期）；`preventDefault` 正确
5. 重显自洽：搜索态下窗口自动隐藏 → 再唤出 → 搜索框自动视觉展开（不抢焦点）、过滤态保持
6. 搜索态挂起自动隐藏；blur/Esc 后恢复倒计时（双保险路径不回归）
7. **双击粘贴回归通过**（零改动区验证：搜索前后粘贴行为一致）
8. 同词对比回归：迁移前后同词搜索结果一致（子串 + `date:` + 标签交集）；258 用例全绿
9. DOM 桩 harness 过；`node --check` 全过；i18n 中英完整
