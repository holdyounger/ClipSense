## 一、需求理解与用户分析

### 1.1 需求本质：人格化升级，不是功能替换

贴边条回答的是「隐藏后怎么回来」（功能问题）；桌宠回答的是「用户为什么愿意让产品一直待在桌面上」（情感问题）。因此桌宠是贴边入口的**人格化升级**：入口职能不变（唤出面板/新内容提示/状态表达），新增陪伴/表达/养成职能。**效率属性不能丢**——桌宠做得再可爱，唤出面板还是第一职责。

### 1.2 目标用户画像

| 人群 | 特征 | 对桌宠的期待 | 优先级 |
|------|------|------------|--------|
| 二次元用户 | 桌面即人设，常驻看板娘/Live2D/VRM 桌宠 | 形象质感（3D）、动作自然、可换形象 | P0-P1 主力 |
| 桌宠培养系用户 | Shimeji（行为型）/ VPet（养成型）类玩家 | 数值成长、互动反馈、收集要素 | P2 |
| 泛效率用户（存量基本盘） | 要的是「不碍事」 | 桌宠**可选、可关、可回退**贴边 | 红线约束 |

### 1.3 产品原则

1. **效率产品人格化，不做人格产品效率化**：桌宠一切行为服务于剪贴板主流程（唤出/提示/反馈/引导）
2. **三态可选**：桌宠 / 贴边 / 纯隐藏，随时切换互为回退（新装默认贴边，决策 1）
3. **隐私红线**：桌宠绝不视觉化剪贴板内容——不显示文本预览、不朗读；情绪反馈只表达「事件类型」（有新内容/复制成功），不表达「内容本身」
4. **单只原则**（决策 6）：桌宠是「产品的脸」，不做多只成群；架构上不做多实例
5. **动画纪律继承**：舞台内渲染、零 setBounds、paint-verified show——桌宠动作沿用 2026-09-17 舞台方案，杜绝 DWM 闪烁回归

### 1.4 生态位参照

- **网易云音乐桌宠**（小M 实机参照，期望的体验基准）：3D 角色常驻桌面。⚠️ 诚实声明：其官方版本号/具体实现技术未从公开渠道检索核实（2026-10-13 检索未获官方技术细节），本 PRD 不引用任何未核实的实现细节，仅以「3D 角色常驻桌面、效果佳」为体验锚点，技术形态按行业标准方案推定
- **Shimeji**（行为型）：常驻可见 + 环境互动心智（参考，不做多只）
- **VPet**（养成型）：数值成长 + 投喂互动（P2 参照，投喂绑使用/互动，决策 3）
- **VRM 桌面伴侣先例**（实证可行）：YUI（Tauri + three.js 渲染 VRM 桌面角色）、ARPAHLS/avatar（MIT 协议，VRM 桌面 overlay）——「透明窗口内 three.js 渲染 VRM」是被验证过的成熟路径

## 二、技术选型（决策 5 调研结论，已定稿）

### 2.1 主技术栈：VRM + three.js（@pixiv/three-vrm）

| 组件 | 选型 | 依据（均已核实） |
|------|------|------|
| 模型格式 | **VRM 1.0**（vrm-c/vrm-specification 开放标准，glTF 2.0 扩展） | 为人形虚拟形象设计的开放格式：标准人形骨骼（Humanoid）、表情（Expressions：happy/angry/sad/relaxed + 自定义）、视线（LookAt）、毛发/裙摆物理（SpringBone 1.0）全部内置规范，天然适配二次元审美 |
| 渲染运行时 | **three.js + @pixiv/three-vrm**（pixiv 官方，npm 包） | GLTFLoader 插件式接入（VRMLoaderPlugin）；MToon 动漫着色器（描边/卡通光影，二次元质感的关键）；v3 起兼容 WebGPURenderer；Electron 渲染进程就是 Chromium，零兼容性障碍 |
| 动画格式 | **VRMA**（VRM Animation 1.0） | 跨模型动画：同一 .vrma 文件可用于任意 VRM 模型——意味着动作库一次制作、全部皮肤通用；three-vrm 提供 VRMAnimationLoaderPlugin |
| 创作工具生态 | **VRoid Studio**（pixiv，免费） | 零建模基础可捏人，导出 .vrm；满足决策 2「开源平台创建形象」 |
| 共享平台生态 | **VRoid Hub**（pixiv，模型共享平台 + 开放 API） | 公开 API（OAuth2 开发者接入）可供外部应用合法使用平台模型——满足决策 2「共享形象」；注意：模型有逐个授权协议（可否转载/商用/需要署名），导入时必须读取并展示 license 元数据 |
| 本地依赖策略 | three/@pixiv/three-vrm 经 npm 打进应用包 | **不依赖 CDN**（产品离线可用；CDN importmap 仅用于原型验证） |

### 2.2 关键技术机制（P0 spike 验证清单）

1. **透明窗口 WebGL 渲染**：petStage 保持 transparent + alwaysOnTop + focusable:false；WebGL canvas alpha 通道合成——先例（YUI/ARPAHLS avatar）已验证可行
2. **轮廓命中**：整窗 `setIgnoreMouseEvents(true, {forward:true})` + three.js Raycaster 对模型网格做射线检测，命中 → `setIgnoreMouseEvents(false)` 接收点击。⚠️ 注意与面板穿透场景相反：此处 forward:true 是**正确的**（桌宠本体需要 hover 反馈；v1 面板「forward 镜像导致视觉反应」的教训不适用于此窗口）
3. **功耗预算**：requestAnimationFrame 帧率钳制（idle 24fps 上限，交互期瞬时 60）；powerMonitor lock/suspend 暂停渲染循环；窗口被完全遮挡时降帧——验收红线 CPU 增量 <2% 不变
4. **paint-verified show**：VRM 资产加载完成 + 首帧渲染确认后才显示窗口（复用 09-17 双 rAF 确认模式），无空白一闪
5. **显存/内存**：VRM 模型典型 10-30MB（VRoid Studio 产出）；单模型常驻 GPU 内存可控，验收时任务管理器取样

### 2.3 落选方案记录

| 方案 | 落选理由 |
|------|---------|
| Live2D | 表现力强，但 runtime 授权费用 + 2D 伪 3D 质感 + 生态闭源（模型制作门槛高）；与「开源生态共享」诉求（决策 2）相悖 |
| 自绘 SVG/PNG 序列帧 | 零成本但无 3D 质感，达不到「一次性最佳效果」要求；降级为「WebGL 不可用时的兜底静态形象」保留 |
| Spine/Lottie | 2D 骨骼动画，同上无 3D；且动作资产不可跨模型复用（VRMA 可） |
| Unity/Godot 嵌入 | 运行时体积（数百 MB）与进程复杂度不可接受；Electron + WebGL 已满足 |

## 三、产品方案（P0-P3 分期）

### P0 · 3D 桌宠最小闭环（spike：VRM 渲染 + 基础交互）

**范围**：直接上 3D 主线（不做 2D 过渡），验证「桌宠形态下唤出体验不劣化 + 3D 渲染功耗达标」。

- 三态设置：桌宠 / 贴边 / 纯隐藏（托盘菜单 + 面板设置区；新装默认贴边）
- 内置默认 VRM 形象 ×1（版权干净的开源模型，候选 VRoid 官方示例模型或购权模型，P0 启动前定）
- 行为四件套：
  - 左键点击 → 唤出面板（等价现贴边条单击）
  - 新条目入库 → 跳动反应（复用 entry pulse 事件源，300ms 内触发）
  - 拖拽移动 → 位置持久化，重启恢复；workArea 边界 clamp
  - 右键菜单 → 唤出面板 / 切换模式 / 设置 / 退出
- 基础活体感：idle 呼吸（程序化骨骼微动）+ **视线跟随鼠标**（three-vrm lookAt，3D 桌宠灵魂特性，成本极低收益极高）
- Alt 按住 → 桌宠穿透 ~~（modifier-passthrough 管辖扩展到 petStage）~~【2026-11-02 修订：恒交互模式（34b9fe4）后桌宠窗口不再参与 Alt 穿透，穿透仅作用于主面板；桌宠恒可交互/可拖拽】
- 引导：首次切桌宠模式复用一次性提示弹窗机制

**明确不做**（P0）：表情系统、VRMA 动画库、形象导入、养成数值、音效。

### P1 · 情绪表达 + 形象导入 + 动作库

- **事件→表情/动作映射**：复制成功（happy 表情+小跳 VRMA）/ 粘贴成功（挥手）/ 清空历史（surprised）/ 长空闲（打盹）/ 夜间时段（睡眠）——只表达事件类型，不涉内容（红线 3）
- **本地 VRM 导入**：设置内导入 .vrm 文件（VRoid Studio 产出），读取并展示模型 license 后生效——「用自己捏的形象」主路径
- VRMA 动作库 v1：idle 轮换（2-3 个）+ 事件动作（4-6 个）；动作与模型解耦（VRMA 跨模型特性）
- 音效开关（决策 4）：默认关，开启后事件配轻量音效
- 全屏应用/游戏自动隐藏（前台窗口 fullscreen 检测）
- 功耗精细档：锁屏/离开暂停；idle 降帧档设置

### P2 · 培养系

- 数值系统：亲密度（主动互动次数）/ 成长等级（**使用天数 + 互动**，决策 3：不绑复制次数）
- 解锁要素：动作/表情/配件（SpringBone 小物）随等级解锁；数据落 storage，支持导出
- 养成事件融入主流程：连续使用、标签整理等正反馈入数值

### P3 · 生态与 AI 生成（决策 2 的远期部分，单独立项）

- **VRoid Hub API 接入**：应用内浏览/导入平台共享形象（OAuth2 开发者接入 + license 合规展示）——决策 2「共享平台」的完整形态
- **AI 形象工坊**（诚实可行性分级）：
  - 文/图 → 3D 网格：第三方服务成熟（输出 GLB 类），但 **无人形骨骼与表情**，不能直接当桌宠
  - 网格 → 可用 VRM：需自动人形绑定（rigging）+ 表情混合形状，当前无一键消费级方案，质量参差
  - **视频 → 桌宠资产：不可行**（需逆向重建网格+骨骼，仅可作参考素材，不承诺）
  - 结论：P3 立项预研「AI 生成 + 自动绑定」管线，近期用户自制形象以 VRoid Studio 官方教程引导覆盖
- 皮肤社区/分发机制

## 四、与现有系统的集成点（开发视角 checklist）

| 集成面 | 改动 |
|------|------|
| 新增依赖 | `three` + `@pixiv/three-vrm`（npm 打包，离线可用） |

| i18n | 桌宠文案 zh/en 双语 |
| 测试 | 状态机/模式切换纯逻辑直测（three 渲染层不可 DOM 桩测，视觉走实机清单）；全量基线 603+ 不可回归 |

## 五、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| **GPU/内存开销**（WebGL 常驻 + 3D 渲染，笔记本敏感） | 高 | 帧率钳制 + powerMonitor 暂停 + 降帧档；P0 验收红线 CPU<2%；超红线则砍描边/阴影等渲染特性分级降载 |
| **低端机 WebGL 透明合成兼容性**（老 GPU/远程桌面场景） | 中 | 启动时 WebGL 可用性探测；不可用自动回退贴边模式并提示（不白屏不崩溃） |
| **默认模型版权** | 高 | 内置模型仅用可商用授权来源（VRoid 官方样例/购权/自制约稿），license 文件随包归档 |
| **用户导入模型的 license 合规**（VRoid Hub 模型各有授权条款） | 中 | 导入时读取 VRM license 元数据并展示；无授权信息的模型给出风险提示后允许使用（责任告知） |
| AI 生成形象期望管理（决策 2 远期部分） | 中 | §3.4 诚实分级已写入 PRD；产品文案不承诺「图片一键变桌宠」 |
| 桌宠遮挡抱怨（比 6px 贴边条大得多） | 中 | 可拖拽 + 尺寸档 + 一键回贴边 + 全屏自动隐藏（P1） |
| 桌宠动作越界舞台（行走类） | 中 | P0-P2 所有动作限舞台内（VRMA 原地类动作）；位移动画 P3 单独立项 |
| 焦点抢夺 | 中 | focusable:false + showInactive 全程不夺焦（现有机制继承） |
| 存量效率用户被默认切换吓到 | 低 | 默认贴边（决策 1），桌宠为可选项 |

## 六、验收标准（P0 spike，测试工程师直接引用）

1. 设置切桌宠模式：贴边条消失，桌宠出现于上次位置（首次=主屏右下角），左键唤出面板与贴边模式功能等价
2. 新条目入库 → 桌宠反应 ≤300ms 触发；动画期间无窗口闪烁、零 setBounds（代码审查 + 实机观察）
3. 视线跟随：鼠标在屏幕移动时桌宠视线平滑追踪（3D 活体感核心体验项）
4. 拖拽 → 位置持久化，重启恢复；拖出屏幕自动 clamp 回 workArea
5. 右键菜单四项可用；切回贴边 → 贴边条回归、桌宠消失，**全量测试 603+ 全绿零回归**
6. ~~按住 Alt → 桌宠整体点击穿透，松开恢复（与面板同语义）~~【2026-11-02 修订：已废弃——桌宠恒交互（34b9fe4），Alt 穿透仅主面板生效且伴随面板透明度降至 0.5 的视觉反馈】
7. 常驻 idle CPU 增量 < 2%（任务管理器 1 分钟取样）；锁屏后渲染循环暂停（任务管理器 CPU 归零验证）
8. 桌宠任何状态不显示剪贴板内容文本（红线核查）
9. 全程不夺焦点：唤出面板后原目标窗口前台身份保持（focus-tracker 链路不回归）
10. WebGL 不可用环境（模拟）：自动回退贴边模式并提示，无白屏无崩溃
