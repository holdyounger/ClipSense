# 源视频的上游生成

主流程（SKILL.md）要的是**带 alpha 的透明素材**。本文档说明这段源视频怎么来。AIGC 环节依赖外部视频生成服务与本地浏览器自动化，属**环境相关步骤**：仓库中只沉淀方法、提示词模板与操作要点，**不得写入任何服务 API Key、Token、账号登录态或机器特定凭据**；服务选择、账号、额度由使用方自行管理。

## 两条路线（先选再动手）

| 路线 | 做法 | 收益 | 前提 |
| --- | --- | --- | --- |
| **A. 透明背景直出（首选）** | 提示词要求透明背景，服务**直接导出带真 alpha** 的视频 | 从源头无绿幕污染，免抠像、免绿边返工 | 服务支持透明背景 + 支持带 alpha 的导出格式 |
| **B. 绿幕抠像（兜底）** | 生成纯绿幕视频，本地 `greenscreen_matte.py` 抠像 | 任意服务都能做 | 接受抠像带来的绿残留，需后续清理 |

> 很多服务的界面会显示棋盘格“透明”预览，但**导出 mp4/H.264 时 alpha 被丢弃**，透明区变成黑底/白底——这不是真透明。是否走 A 路线，取决于服务能否**导出带 alpha 的文件**，而不是预览长什么样。

## 目标产物规格（两路线通用）

| 项 | 要求 |
| --- | --- |
| 画幅 | 1:1（桌宠窗口近方形） |
| 分辨率 | 480×480（起步够用；边缘质量优先于分辨率） |
| 帧率 | 24fps |
| 时长 | 5s（待机动作循环） |
| 角色 | 悬浮居中，全身入镜，固定正面机位，无镜头移动，无文字水印 |
| 背景 | 路线 A：**透明（alpha=0）**；路线 B：纯净均匀纯绿，无地面/阴影/环境 |

## 路线 A：透明背景直出

### 提示词模板（图生视频）

参考图 = 已审核的角色定妆图（透明/灰底/绿幕均可，需与动作一致的形象基准）。提示词骨架：

> 同一只 {角色描述}，保持参考图中的脸、毛发、{配饰}和比例完全一致。角色置于**完全透明背景**上，主体之外无任何背景、无地面、无地板、无阴影、无桌子或任何环境元素，角色悬浮，边缘干净锐利、毛发细节完整。做{动作描述}。固定正面机位，全身入镜，无镜头移动，无文字水印，动作平滑。

动作描述示例（待机 d1）：

> 做自然待机动作：身体重心缓慢左右轻摆，头部轻轻转动，耳朵和尾巴有细微跟随，呼吸起伏自然，表情友好平静。

要点：
- 强调“**完全透明背景 / 主体之外无任何元素**”，别让服务脑补场景。
- 明确“**角色悬浮、无地面/阴影**”——有投影就说明它没按透明背景处理。
- 强调“**边缘干净、毛发细节完整**”——毛发边缘是 alpha 质量的关键。
- 参考图是形象一致性的锚点，动作提示词不要改角色外貌描述。

### 导出格式（决定成败）

**只有能承载 alpha 的格式才算数**：

- ✅ WebM VP9（`yuva420p`，浏览器可直接用，桌宠最省事）
- ✅ ProRes 4444 `.mov`（后期交换，质量最好，文件大）
- ✅ PNG 序列（逐帧，最稳，便于调试）
- ❌ 普通 MP4 / H.264 / H.265：不含 alpha，导出即失真成黑/白底
- ❌ 只看棋盘格预览：不算证据

### 导出后必做验证

按 [verification.md](verification.md) 第 0、1 节的 PNG→cv2 路线确认：

- `a_min == 0`、有一定比例的透明像素（说明 alpha 真存在）
- a=0 像素平均 G ≈ 0（透明区无残留颜色；有则按 SKILL.md 第 5 步 `alpha_repair.py` 清零）

**验证通过**才算省掉抠像；若 alpha 全不透明（导出丢 alpha），退回路线 B。

## 路线 B：绿幕抠像（兜底）

### 绿幕提示词模板（图生视频）

> 同一只 {角色描述}，保持参考图中的脸、毛发、{配饰}和比例完全一致。整个画面背景必须是纯净均匀的纯绿色绿幕，全程保持纯绿背景不变，不允许出现地面、地板、阴影、桌子或任何环境元素，角色悬浮在纯绿背景前。做{动作描述}。固定正面机位，全身入镜，无镜头移动，无文字水印，动作平滑。

要点：
- 强调“**全程保持纯绿背景不变**”——防止生成中途背景漂移成其他颜色。
- 明确“**角色悬浮、无地面/阴影**”——防止出现地板/投影（这是抠像斑驳的首要污染源）。
- 拿到 mp4 后交给 SKILL.md 第 1B 步抠像，再按第 5 步 `alpha_repair.py` 清理 a=0 与半透明绿残留。

## 生成参数

- 模型档位：免费档（排队）或优先生成（付费/积分），按可用性选。
- 480p / 5s 起步验证；确认边缘质量后再考虑 720p。
- 一次动作一支视频；待机/点击/拖拽各自单独生成。

## CDP 驱动浏览器（可选加速）

若用户本地浏览器以远程调试端口（如 Chrome/Edge `--remote-debugging-port=9222`）开启，可通过 CDP 自动填写表单、上传参考图、触发下载，免去手工操作。仓库的 `scripts/pet-generate/a01_batch.py` 已用 Python（`websocket-client` 直连 CDP）实现批量提交/下载，**跨平台**（Windows/macOS/Linux 均可），不再依赖任何系统脚本或固定下载目录。要点：

1. 连接 `http://127.0.0.1:9222/json` 找到目标页的 `webSocketDebuggerUrl`。
2. 上传用 `DOM.setFileInputFiles` 指向本地参考图路径。
3. 触发下载用 `Browser.setDownloadBehavior` 指定落盘目录，再点产物下载链接。
4. 轮询任务状态（队列/渲染中/完成），完成后取下载链接。
5. 若服务提供导出格式选项，用 CDP 选中带 alpha 的格式（路线 A）；否则按路线 B 下载绿幕 mp4。

**边界**：
- CDP 脚本若需入仓库，只保留**通用、无凭证**的命令（连端口、找页、上传、下载），不含登录态。
- 页面 DOM 结构可能随服务改版变化，选择器要可维护、失败要可诊断，不要硬编码脆弱路径。
- 排队/渲染耗时不可控，脚本须支持超时与幂等重试。

## 拿到源视频后

- 路线 A（真 alpha）：先按 verification.md 验证，通过则直接走 SKILL.md 第 2/3 步编码部署（已是 yuva420p WebM 的可跳过编码）。
- 路线 B（绿幕）：交给 SKILL.md 第 1B 步抠像起。
